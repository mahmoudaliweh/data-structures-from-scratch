# TrieA Trie is a tree where each node represents a character.Each path from root → node forms a prefix.Each path from root → terminal node forms a word.# Why Tries?A Trie (Prefix Tree) is designed to efficiently store and retrieve strings, especially when:* You need fast prefix lookups* You handle large dictionaries* You need auto-complete or suggestion systems* You must avoid repeated string comparisonsIt optimizes operations that depend on common prefixes.# AdvantagesFast prefix queriesDeterministic lookupGreat for autocompleteAvoids repeated prefix comparisons# DisadvantagesSparse children waste spaceCache-unfriendlyHigh memory usage:Every Character Becomes a NodeIf you store 1 million 10-letter words:HashMap → 1 million stringsTrie → up to 10 million nodesEvery node contains:A children structure (dict / array)A boolean flag (is\_end)Even if a node represents just one character, it still carries this full structure.In many implementations, nodes use a fixed array of size 26 (for lowercase letters).Even if a node has only 1 child:25 slots are emptyBut still allocatedThis becomes massive overhead.Worst Case: No Shared PrefixesTries are memory-efficient only when words share prefixes.# ApplicationsSearch Engine; Autocomplete systems like: Google, Bing.Mobile Keyboards; Predictive typing, Word completion, Spell correctionNetworking; IP routing uses binary tries to match prefixes efficiently.# Time Complexity|Insertion|O(len)||-|-||Search|O(len)||Deletion|O(len)|
